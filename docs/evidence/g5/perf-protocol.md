# G5 native performance protocol

This protocol extends the existing opt-in `BuildDiagnostics`, not a separate profiler manager. No Unity execution or measurements are implied by this document. Actual evidence belongs beside it with command lines, Player logs and timestamps matching source/build. Keep G4 baseline evidence unchanged: High direct-executable 27.97 FPS/P95 71.75 ms versus foreground approximately 60 FPS/P95 approximately 17.5 ms. Cause is unknown; a code change alone does not prove the variance fixed.

Run an actual graphical Release native Player (without `-nographics`), using `-wattshiftEvidence -wattshiftSmoke -wattshiftEvidenceOutput <absolute-directory> -wattshiftProfileSeconds 45`. The duration defaults to 10 seconds, clamps to 10–120; malformed/nonfinite values revert to 10. Keep foreground focus and record launch method/display/device/OS/power state. `developmentBuild` records `Debug.isDebugBuild`; require false for Release evidence. The evidence flag isolates saves/settings. Never use this run as browser/mobile or human-play acceptance.

The walkthrough captures the clean real menu, starts the school scenario, pauses at 20:00 with its actual night street lighting, visible problem markers and the expanded gameplay solutions card. It measures Low/Medium/High after one-second settling per tier for the requested duration. Screenshot work is outside measurement windows. It then measures 10 seconds of the same High scene/card with the actual `GameSession.Update` clock at 4×; no synthetic Tick runs within that active window. Start/end simulation hours must increase. Focus loss may pause the clock: this is reported and must be investigated, not hidden. Subsequent existing speed-selection, school save/load and all three mission completion checks remain.

Measurements use intervals between successive end-of-rendered-frame completions, excluding recorder initialization. Mean FPS is 1000 / mean interval milliseconds. The 1% low is 1000 / mean of the worst ceil(N×0.01) intervals, minimum one; it is not a percentile FPS. P50/P95/P99 use nearest-rank interval percentiles. Report maximum interval, counts above 33/50/100 ms, interval count, rendered frames, wall seconds, focused-sample count/fraction and active sample simulation hours. This is sampled frame timing, not Unity GPU timing or a CPU profiler attribution. Frame-boundary sampling overhead is included.

Draws/batches use median positive ProfilerRecorder samples and report sample counts. A zero-only or unavailable recorder is invalid data, never zero draw calls; Release builds may strip these counters. Unity allocated/reserved values are sample-end allocator snapshots with availability status, not full process or GPU memory. On desktop, Process.WorkingSet64 is a separately labeled sample-end resident working-set snapshot, with explicit unavailable status on unsupported/failed/nonpositive reads. No per-frame scene enumeration is performed. Scene object/reference inventory runs outside measurement: active objects, enabled lights/shadow lights, unique mesh-renderer materials/meshes (including inactive renderer references), audio sources and loaded clips. Audio clip/source counts and settings do not verify audible output or human sound quality.

Scene-ready load scope is the player realtime-since-startup timestamp on the diagnostics frame where session/HUD/markers are ready, after two startup frame yields. It includes engine/scene initialization before that observation, excludes OS launch/download and is not an instrumented scene-load API duration.

After the walkthrough, isolated PlayerPrefs store volume 0.37, muted true and Medium quality; PlayerPrefs.Save flushes them. Reopen the same built Player in a fresh process with `-wattshiftEvidence -wattshiftSmoke -wattshiftRestoreSmoke -wattshiftEvidenceOutput <separate-restore-directory>`. That path verifies campaign restoration and reads audio/quality initialized by their actual Awake methods; `settingsRestoredInFreshProcess` must pass. Session.Load within the first process alone is insufficient proof. Human listening remains unverified.

Marker optimization retains source anchors, marker size/colors/connectors/pulses and HUD obstruction rules. It caches projection/occlusion until camera/screen changes; placement invalidates on HUD/context geometry changes, settings scale, problem-presence changes and modal/activity changes. Geometry callbacks bind after HUD initialization regardless of Start order. This assumes static source diorama colliders; moving/destroyed scene geometry would need explicit projection invalidation. Check actual paused and active markers after selection, camera movement, card expansion, settings, scale and portrait changes before accepting visual parity. No visual-quality reduction is claimed or intended.

Record source file UTC mtimes/hashes, built executable and Player log timestamps, screenshot paths and raw native-smoke.json for each run. Compare release paused/active runs with focus fractions, without attributing changes to marker caching until measured. Windows, Web browser, phone, thermal stability and human play/listening remain separate gates when not actually exercised.
